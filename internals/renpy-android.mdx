Ren'Py ships with built-in Android tooling that lets a visual novel detect its runtime environment and adjust behaviour accordingly. This port of Doki Doki Literature Club! leans on that system heavily — swapping keyboard-centric inputs for touch events, registering a dedicated audio channel for the poem minigame, and clamping the rendered viewport to a strict 16:9 ratio so the original 1280×720 artwork never distorts on a widescreen phone.

## Display Initialisation

The game's virtual canvas is established early in `gui.rpy` with a single call that locks every layout calculation to DDLC's original resolution:

```python
init -2 python:
    gui.init(1280, 720)
```

All `xpos`, `ypos`, and size values in `gui.rpy` and `screens.rpy` are expressed in these virtual pixels, and Ren'Py automatically scales up to fill the physical display. The `force_integer_multiplier` function defined in `options.rpy` keeps that scaling honest by snapping to a 16:9 aspect ratio rather than stretching to fill irregular screen shapes:

```python
def force_integer_multiplier(width, height):
    if float(width) / float(height) < float(config.screen_width) / float(config.screen_height):
        return (width, float(width) / (float(config.screen_width) / float(config.screen_height)))
    else:
        return (float(height) * (float(config.screen_width) / float(config.screen_height)), height)
```

This function receives the physical display dimensions and returns a corrected pair that preserves the `config.screen_width / config.screen_height` ratio, preventing letterboxed padding from introducing visual artefacts on tall or ultra-wide Android devices.

## Touch Variant Detection

Ren'Py exposes `renpy.variant("touch")` to query whether the current platform is a touch-screen device. The port uses this flag at `init -2` priority — before any screen is drawn — to apply touch-specific border corrections to the quick-access button bar:

```python
init -2 python:
    if renpy.variant("touch"):  # Quick buttons borders fix
        gui.quick_button_borders = Borders(18, 7, 20, 0)
```

On desktop the default borders leave the quick-menu buttons flush with the bottom edge of the screen, which is fine for a mouse cursor. On Android those same dimensions clip the touch targets. `Borders(18, 7, 20, 0)` widens the left padding to 18 px and the right to 20 px, giving fingertips a comfortable hit area without altering the visible button artwork.

## Keymap Overrides

The PC version of DDLC maps right-click (`mouseup_3`) to the game menu, but on Android a right-click event is typically generated by a long-press — a gesture players use to hide the dialog window. The port remaps this in `definitions.rpy`:

```python
init python:
    config.keymap['game_menu'].remove('mouseup_3')
    config.keymap['hide_windows'].append('mouseup_3')
    config.keymap['self_voicing'] = []
    config.keymap['clipboard_voicing'] = []
    config.keymap['toggle_skip'] = []
```

<Steps>
  <Step title="Remove from game_menu">
    `mouseup_3` is stripped from the `game_menu` keymap so a long-press no longer opens the save/load overlay.
  </Step>
  <Step title="Add to hide_windows">
    The same event is appended to `hide_windows`, matching the gesture players expect from reading other Android visual novels.
  </Step>
  <Step title="Clear voicing and skip keys">
    `self_voicing`, `clipboard_voicing`, and `toggle_skip` are set to empty lists. The original PC bindings (`v`, `shift+c`, `ctrl`) conflict with Android text-input scenarios and are unused on mobile.
  </Step>
</Steps>

## Audio: The music\_poem Channel

The poem-writing minigame requires its own looping background track that stays tightly synchronised with the word-selection UI. A dedicated Ren'Py audio channel is registered for this purpose:

```python
renpy.music.register_channel("music_poem", mixer="music", tight=True)
```

`mixer="music"` ensures the poem track obeys the player's music volume slider. `tight=True` tells Ren'Py to cut the track immediately when the channel is stopped rather than fading out — important because the minigame can end abruptly and a lingering fade would bleed into the next scene's audio. Music playback position is tracked by the `get_pos` helper:

```python
def get_pos(channel='music'):
    pos = renpy.music.get_pos(channel=channel)
    if pos: return pos
    return 0
```

## Image Cache Tuning

Android devices have less VRAM headroom than desktop PCs. Two `options.rpy` constants limit how aggressively Ren'Py pre-loads images:

```python
define config.image_cache_size = 64
define config.predict_statements = 50
```

`image_cache_size = 64` caps the decoded-image cache at 64 entries, preventing the app from accumulating hundreds of character-sprite composites in memory. `predict_statements = 50` tells the engine to look 50 script statements ahead when pre-loading; on a low-RAM device this prevents stutter without triggering out-of-memory kills during long dialogue sequences.

<Note>
  `config.developer` is currently set to `True` in `definitions.rpy`, which enables Ren'Py's developer overlay (displaying the current script file and line number) and expands the quick menu with a **Devtools** button. Set `config.developer = False` before building a release APK.
</Note>
